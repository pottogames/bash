# מבנה הפרויקט וזרימת העבודה

המסמך הזה עונה על שאלה אחת: **מה צריך להיות בכל רמה בהיררכיה, ולמה הרמה הזו קיימת בכלל.**

הכלל שמנחה את כל המסמך: *לרמה יש זכות קיום רק אם מישהו באתר מבקש סכום בדיוק בה.*
כל רמה למטה מצדיקה את עצמה בשאלה אמיתית שמישהו שואל.

---

## ההיררכיה

```
פרויקט            ← מה שהלקוח חותם עליו ומשלם עליו
└── מבנה           ← מה שמקבל היתר משלו, מנוף משלו, לוח זמנים משלו
    └── קומה       ← לאן קבלן נשלח בשבוע נתון; הרמה שבה קומות חוזרות
        └── אזור   ← מה שנמסר כיחידה: דירה, לובי, חניון
            └── חלל ← חדר בודד. אופציונלי.
```

---

## פרויקט

**השאלה שהרמה עונה עליה:** "כמה עולה הפרויקט?"

| מה נשמר | למה |
|---|---|
| שם, קוד עבודה פנימי, לקוח | זיהוי מול הנהלת חשבונות |
| כתובת, עיר, גוש/חלקה | היתרים, אגרות, הובלות |
| סטטוס | טיוטה → כמויות → הצעה → מכרז → ביצוע |
| **גובה קומה ברירת מחדל** | המספר הכי שימושי בכל התהליך. כל שטח קיר וכל נפח בטון תלוי בו. נשמר ברמת הפרויקט ונדרס למטה |
| מטבע, שיעור מע״מ | חישוב הצעה |

**סכומים ברמה הזו:** סה״כ הצעה, סה״כ עלות, מרווח כולל, סה״כ שטח בנוי.

---

## מבנה

**השאלה:** "כמה עולה בניין B?" — ובפרויקט עם שני בניינים זו שאלה שנשאלת שבועית.

| מה נשמר | למה |
|---|---|
| שם, קוד | "בניין A", "מבנה מסחרי" |
| סדר תצוגה | בניינים לא ממוספרים לפי אלפבית באתר |

**סכומים:** כל הכמויות של הקומות שמתחתיו, סה״כ שטח בנוי, סה״כ עלות.

**למה זו רמה נפרדת ולא שדה על הפרויקט:** בניינים יוצאים לביצוע בזמנים שונים.
חבילת עבודה לקבלן שלד של בניין A לא יכולה לכלול את בניין B, שיוצא בעוד חצי שנה.

---

## קומה

**השאלה:** "מה הקבלן עושה השבוע?" ו-"כמה קומות טיפוסיות יש?"

| מה נשמר | למה |
|---|---|
| `level` — מספר קומה חתום | ‎−2 מרתף שני, 0 קרקע, 900 גג. ממויין נכון וזה מה ששמות שכבות מקודדים |
| שם, קוד | "קומה 3", "מרתף חניה" |
| מפלס מוחלט (מטרים) | חישוב עומק חפירה, אורך פירים, גובה משאבות |
| **גובה קומה** | נדרס מהפרויקט. קומת קרקע כמעט תמיד גבוהה יותר |
| שטח ברוטו / נטו | בקרת שפיות מול הכמויות שנמדדו |
| **`repeat_count`** | קומה טיפוסית ×8 — נשמרת פעם אחת, הכמויות שלה מוכפלות |
| `repeats_floor_id` | קומה שמשקפת אחרת |

**סכומים:** כתב כמויות מלא לקומה, לפי מקצוע.

### למה קומה טיפוסית היא לא שכפול

הפיתוי הוא לשכפל את הקומה שמונה פעמים. הבעיה מגיעה שבועיים אחרי:
מישהו מגלה שהמדידה של הריצוף שגויה, ועכשיו צריך לתקן אותה בשמונה מקומות —
ובפועל מתקנים בשבעה. `repeat_count` שומר עותק אחד ומכפיל בזמן החישוב, כך שתיקון
אחד מתקן את כל השמונה. זו כל הסיבה שהמושג "קומה טיפוסית" קיים במקצוע.

מגבלה שנאכפת בסכימה: קומה שמשקפת קומה אחרת לא יכולה גם להיות טיפוסית בעצמה,
אחרת אותה כמות מוכפלת פעמיים.

## אזור

**השאלה:** "כמה עולה דירה B?" — זו השאלה שלקוח שואל, במילים שלו.

| מה נשמר | למה |
|---|---|
| סוג | דירה / לובי / חניון / ליבה / פיר / מחסן / מסחר / טכני / ממ״ד / גג / חוץ / משותף |
| שם, קוד | "דירה 3", "לובי כניסה" |
| שטח ברוטו / נטו | הבסיס לתמחור |
| **שטח מרפסות בנפרד** | מרפסת מתומחרת אחרת מפנים. איחוד שלה לשטח נטו מעלם את ההפרש |
| היקף | פנלים, סוקל, טיח היקפי |
| מספר חדרים (3.5) | תמחור לפי חדר, השוואה לשוק |
| **קו מתאר (`outline`)** | מצולע בקואורדינטות התוכנית. זה מה שמאפשר לשייך ישות שנמדדה לאזור אוטומטית |

**סכומים:** כמויות לפי מקצוע, עלות, מחיר ללקוח, מחיר למ״ר.

### איך כמות מגיעה לאזור בלי להיספר פעמיים

שכבה שנמדדת בתוכנית קומה נתלית על **הקומה**. אם הגאומטריה של ישות בודדת נופלת
בתוך קו המתאר של אזור, גם ה-`zone_id` מתמלא — אבל השורה נשארת אחת.
סיכום לפי קומה סוכם את כל השורות של הקומה; סיכום לפי אזור מסנן לפי `zone_id`.
אותה שורה, שתי שאלות, ספירה אחת.

## חלל (חדר)

**השאלה:** "מה הגמר בחדר רחצה הורים?"

| מה נשמר | למה |
|---|---|
| שם, קוד | "סלון", "חדר רחצה הורים" |
| שטח רצפה, שטח קירות, שטח תקרה | שלושה מספרים שונים לשלושה מקצועות שונים |
| היקף | סוקל, פנלים |
| גובה נטו | תקרה אקוסטית משנה אותו לעומת הקומה |
| קו מתאר | שיוך אוטומטי |

**מתי כדאי למלא:** רק כשהמפרט משתנה בין חדר לחדר. בפרויקט עם מפרט אחיד
הרמה הזו מוסיפה מאות שורות בלי להוסיף שום מידע.

## זרימת העבודה מקצה לקצה

```
1. הקמת פרויקט
   └─ מבנים → קומות → אזורים.
      אפשר להזין ידנית, או לתת למערכת לזהות קומות משמות השכבות
      (״קומה 3״, ״ק3״, ״floor 3״, ״מרתף״) ולאשר.

2. העלאת תוכנית
   └─ הקובץ נכנס לבאקט פרטי ומוצפן. נוצר job בתור.
      ה-worker קורא, מוציא CanonicalPlan, וקובע קנה מידה.

3. קנה מידה  ← נקודת העצירה הראשונה
   ├─ הקובץ מצהיר על יחידות → נקרא, מאומת מול המידות, ביטחון 100%
   ├─ לא מצהיר אבל יש מידות → מוסק, ביטחון ≤85%, באנר אזהרה
   └─ אין כלום → חסום. חייבים כיול ידני לפני שממשיכים.

4. סיווג שכבות  ← נקודת העצירה השנייה
   ├─ כלל ארגוני קיים (מתיקון קודם) → 98%
   ├─ תקן AIA/ISO בשם השכבה → 90%
   ├─ מילון מונחים עברית/אנגלית → לפי משקל
   └─ תוכן השכבה בלבד → סוג מדידה בלבד, המקצוע נשאר לאדם
   כל שכבה מתחת ל-70% ביטחון נכנסת לתור בדיקה.

5. כתב כמויות
   └─ מדידה גאומטרית לכל שכבה, לפי הקומה/אזור שהיא שויכה אליהם.
      כל שורה נושאת את מזהי הישויות שהרכיבו אותה, אחוז פחת,
      ומכפיל קומה טיפוסית.

6. הצעת מחיר
   └─ מחירון × כמויות + מרווחים. גרסאות, לא עריכה במקום.
      עלויות ומחירי מכירה בטבלאות נפרדות.

7. חבילות עבודה
   └─ בחירת מקצוע + היקף (מבנים/קומות/אזורים) → חבילה.
      ה-worker מרנדר תוכנית חדשה שמכילה רק את השכבות של החבילה,
      ממותגת בשם החברה של הנמען.

8. הזמנת גורמים
   └─ אדמין מנפיק קוד הזמנה → מייל → הגורם נרשם →
      אדמין בודק תפקיד והרשאות ומאשר → הגורם נכנס ורואה
      רק את החבילה שלו, עד תאריך תפוגה.

9. הצעות קבלנים
   └─ מילוי מחירים בפורטל, כולל אפשרות לחלוק על הכמות שנמדדה
      (הכמות שלו נשמרת לצד שלנו, לא במקומה).
      השוואה זו מול זו → זוכה → העלות שלו נכנסת לגיליון המרווחים.
```

## נקודות העצירה — ולמה הן מכוונות

בשני מקומות המערכת מסרבת להמשיך לבד:

1. **קנה מידה לא ודאי.** טעות כאן מכפילה את כל המספרים בפקטור 10 ונראית תקינה
   לחלוטין. אין שום סיבה לנחש, ולכן המערכת חוסמת הפקת הצעה עד לכיול.

2. **סיווג בביטחון נמוך.** שכבה בשם `Layer1` יכולה להיות כל דבר. המערכת אומרת
   מה היא כן יודעת (סוג המדידה, מתוכן השכבה) ומשאירה את המקצוע לאדם.

בשני המקרים ההחלטה של האדם נשמרת ככלל ארגוני ולא נשאלת שוב.
